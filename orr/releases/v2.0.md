# ORR 2.0: one system, accountable

*Released 2026-10-02. Default in-season model: `--model 2.0`. Models 1.9 through 1.0 remain reproducible. The frozen 2026-27 preseason file (ORR 1.0) is unchanged. 2.0 forecasts exactly as 1.9 does: `test_live_2_0` checks that their switches are identical.*

## Why

Through 1.9, ORR shipped eleven versions in two days. Each had its own evidence, and that evidence was spread across eleven release notes, about a dozen backtest files and a website accuracy section that had grown by accretion. Four questions had no single answer:

- What exactly is running today?
- How will ORR be judged against NeurHL?
- Can a published forecast be checked?
- Where are the results in one place?

2.0 adds no new forecasting. It answers those four questions, and it fixes the terms of the season-end comparison before the season can influence them.

## What is new

| Feature | Where | Notes |
|---|---|---|
| **Preregistered season-end evaluation.** | `orr/EVALUATION_2027.md`, `orr/evaluate_2027.py` → `orr/output/evaluation_2027.json` | Committed when 8 of 1,344 games were in the results file and no ORR daily forecast had yet been scored. It holds the SHA-256 of every evaluated file. There are four primary comparisons, each a paired bootstrap 95% CI (2,000 resamples, seed 7), with a verdict only when the CI excludes zero:
  - P1, ORR daily vs NeurHL-G, game log loss;
  - P2, preseason files, game log loss;
  - P3, team points MAE;
  - P4, skater points MAE at 40+ GP.

  Secondary results are reported but not judged: CRPS, coverage, Brier, goalie save % and NeurHL 1.0. Until the last regular-season game every line reads "pending" or "interim (not a verdict)". There is no overall winner by majority. |
| **Reproducibility check.** | `python3 -m orr.reproduce --date D` → `orr/output/reproduce/reproduce_D.json` | Checks out the recorded code commit in a temporary git worktree. Rebuilds the exact inputs: the results file found in git history by its SHA-256, and exactly the recorded lineup files, each matched by SHA-256 from the recorded paths, `--lineup-dir` or NeurHL's origin/main. Re-runs the day with the recorded model, seed and simulations, and compares every output file, ignoring only the `created_utc` time stamp. The daily Action re-runs the previous day's forecast. |
| **Model card.** | `orr/site/build_model.py` → `docs/orr/model.html` | Built from the code's own records: the `MODELS` table, the parameter files that hold each adoption decision, the evaluation file and the reproducibility reports. For every switch it gives the version that added it, what it does, its held-out evidence with a link, and its state: "live", "off (by its test)" or "off". |
| **One accuracy section.** | Website "Model accuracy" | It opens with one table of held-out results for every layer, including the failures. Next is a season scorecard of every forecast on its eligible games (log loss, Brier, picked winner, Δ vs ORR daily), then the preregistered evaluation's status. Running log loss, reliability and paired panels follow. |

- **P2:** interim. One game, not a verdict.
- **P3 and P4:** pending until the season is complete.

`test_live_2_0` adds nine checks:
- the bootstrap verdicts;
- interim results that are not verdicts;
- the team CRPS formula;
- the season-end comparisons (P3, P4, goalies) run on a synthetic complete season, so those branches are exercised now and not first in April;
- season-completeness;
- the reproduce comparison, which ignores only the time stamp;
- that only recorded lineup files are copied;
- that 2.0 forecasts as 1.9 does;
- that the model card's states follow the parameter files.

All 14 suites pass (66 tests).

## Retrospective: 1.0 to 2.0

The version series was meant to simulate about a year of iterated progress. Each version's held-out result was measured once, on seasons its tuning never saw.

| Version | Theme | Main change | Held-out result | State in 2.0 |
|---|---|---|---|---|
| 1.0 | First release | Market-anchored preseason file and in-season filter | Game file vs preseason Elo: −0.0044 log loss (CI −0.0067 to −0.0024) | Frozen |
| 1.1 | Lineup-aware | X1: dressed lineups and starters in the filter | −0.00130 (CI −0.00255 to −0.00006); −0.00232 on two unused seasons. Eight other hypotheses were not accepted. | Live |
| 1.2 | Player-level | Skater rates updated in-season | Rest-of-season points MAE −0.41 (CI −0.49 to −0.34) | Live |
| 1.3 | Live = backtest | Box-score-first lineups, goalie talent; Platt check | Platt worsened log loss | Live; Platt off |
| 1.4 | Standings race | Drift-calibrated in-season odds, start shares; absences | CRPS 3.84 vs 4.99; starts MAE −0.83 (CI −1.12 to −0.56); absences +0.0008 | Live; absences off |
| 1.5 | Calibration | NB shots; standings sharpness | −0.00021 log loss; sharpness tuned to 1.0 | Live; sharpness no-op |
| 1.6 | Full picture | Upstream NeurHL scoring, goalie table, SOS, rest-of-season file | Descriptive | Live |
| 1.7 | Current by default | In-season site, rest-of-season intervals (v = 3) | Interval score −2.76 (CI −3.07 to −2.43); coverage 0.62 → 0.73 | Superseded by 1.8 |
| 1.8 | Fix what 1.7 measured | Intervals v = 6 with injury spells; goalie rest-of-season file; forecast diff | −0.46 (CI −0.73 to −0.18); coverage 0.80 | Live |
| 1.9 | Beating NeurHL? | Paired live comparison, player reliability, clinch flags | No tuning | Live |
| 2.0 | Accountable | Preregistered evaluation, reproduce, model card | Two of two published days reproduce exactly | Live |

**What the series taught.**

- **Large forecast gains came early.** X1 (1.1) and the in-season player, start-share and standings updates (1.2 and 1.4) moved held-out error by amounts with CIs well clear of zero. From 1.5 on, the measurable gains were in calibration of intervals and distributions, not in game accuracy.
- **Three of fourteen tested ideas failed.** Long-term absences, the Platt correction and sharper standings all failed their rules and ship switched off. The pre-declared rules did their job: none of them would have been visible as a failure in a single season of live play.
- **The live record is still almost empty.** Eight games have been played. No ORR daily forecast has yet resolved on a game it was eligible for. The season scorecard and the preregistered evaluation are the honest place to look, and they will not say anything decisive for months.
- **The decisive inputs are operational.** Shots on goal enter the live update only through the daily GitHub Action. Its backtest edge over goals alone is 0.0022 log loss, larger than any single feature added after 1.1. The Action runs only once this branch is on the default branch.

## Limits

- 2.0 does not improve accuracy. Its value is that the season-end comparison is fixed in advance and that any published day can be checked.
- `orr.reproduce` needs the ignored working inputs (`orr/cache`, `data/raw/fastrhockey`) to be present, as they are wherever the daily loop runs. It compares the cached inputs as they are now. A change to the cache since the run would show as "differs", not be hidden.
- Goalie rest-of-season intervals and playoff-round probabilities still have no held-out test. 2.1 plans both.
